# Devpost / Submission Template

Fill in this order. Keep each section scannable: short paragraphs, bold the first phrase of key bullets.

## Project name
2 words max, pronounceable, searchable. Avoid generic names ("StudyAI").

## Tagline (≤ 200 chars)
`<Product> helps <specific user> <do outcome> by <unique mechanism>.`

## Inspiration (3–5 sentences)
A specific moment or person. One stat. Why this team cares. No "In today's fast-paced world".

## What it does (5–8 sentences or bullets)
Walk the demo path as a story. First sentence = the core value. Include the wow moment explicitly. Mention the user's input and the output they get.

## How we built it
- Architecture in one sentence.
- Frontend, backend, AI, data, deploy — one line each, with why.
- **Use of <sponsor 1>**: what it does in the product, why it was the right tool.
- **Use of <sponsor 2>**: same.
- Link or embed the architecture diagram.

## Challenges we ran into (2–4 bullets)
Real technical problems from NOTES.md, each with the fix. Shows engineering depth.

## Accomplishments we're proud of (2–4 bullets)
Measurable where possible: latency achieved, accuracy on test set, users who tried it at the venue.

## What we learned (2–3 bullets)
Specific, technical or product. Not "teamwork".

## What's next (3 bullets)
Includes everything mocked, framed as roadmap. One user/market step.

Tags for every language, framework, API, sponsor product.
