### Translation cheatsheet
| Common criterion | Judge needs to see | Cheapest strong evidence |
|---|---|---|
| Innovation / Originality | something they haven't seen today | one novel interaction, not a novel stack |
| Technical complexity / Execution | a hard part working live | reasoning/retrieval panel + 6-box architecture diagram |
| Impact / Usefulness | real user + number | a quote from someone at the venue, one stat |
| Design / UX | smooth happy path | consistent component library, no raw errors, good empty states |
| Completeness / Functionality | end-to-end on live URL | judge tries their own input |
| Presentation | clear story | hook in 10 s, rehearsed timing |
| Sponsor tech use | sponsor product central | sponsor call on the demo path, named in pitch and diagram |
| Social good / Theme fit | theme visible in the problem | user from the theme's population |

### Score anchors
- **Wow 5**: a judge says "wait, do that again". **Wow 1**: looks like a form with an AI button.
- **Originality 5**: no close match in Devpost search for 3 phrasings. **1**: last year's winner of this event.
- **Build 5**: core spike done in < 1 h by someone on the team. **3**: core uses a known API pattern nobody has used. **1**: needs training a model at the venue.
- **Anchor fit 5**: the wow moment IS the anchor criterion.

## C. Self-score before submission

Score your own project as the judge would, using section A. Any criterion under 3 gets one fix before freeze, or one sentence in the submission and pitch that addresses it.
