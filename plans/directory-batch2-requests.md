# Independent requests for directory batch 2

Each reviewer receives the finished skills and these requests, without model answers. Produce actual outputs, then record limitations and findings. These text executions do not demonstrate application implementation or cross-model reliability. All organizations and people below are fictional.

## IXA-001

1. Studio Pine's interactive lesson moves a marker between two diagram regions to show a transfer. A learner requests reduced motion. Design an alternative that preserves the lesson's meaning; no running interface is available.
2. A team asks to remove all animation from its product but supplies no inventory, user preference behavior, or explanation of which animations communicate task state. Prepare a bounded response.
3. A loading indicator stops moving when reduced motion is selected, leaving the user unable to tell pending work from a frozen interface. Specify recovery without assuming a successful completion.

## IXA-002

1. An assistant hears 'move it to Friday' while two tentative meetings are in context and no Friday date or timezone is established. Draft the repair turns, without editing a calendar.
2. A voice ordering prototype receives an unclear item name. No product catalog or speech confidence score is available. Draft its clarification path.
3. A user corrects a previously confirmed destination while a voice system says submission is pending. Design the next turns without asserting cancellation or submission succeeded.

## SDR-001

1. An animator reports a sleeve collapsing only when a character raises an arm while twisting the torso. Prepare a pose comparison specification from that description; no rig file is available.
2. A team wants to certify that its rig works in every pose based on one neutral screenshot. Respond with a bounded review and missing inputs.
3. A visible tear appears in a posed character, but the team changed both mesh topology and rig weights between the baseline and new version. Design a discriminating comparison.

## SDR-002

1. A museum scan contains a hole where the scanner could not see behind a handle. Prepare a cleanup record that distinguishes measured surface from a proposed filled patch.
2. A client sends an attractive mesh without raw scans, scale references, or processing history and asks for a certified faithful cleaned original. Prepare a bounded response.
3. A cleanup operator smooths away a small asymmetric notch, then learns it may be an intentional identifying feature. Prepare a recovery and provenance plan with no claim files were restored.

## CLI-001

1. A batch-processing command must emit one machine-readable result while showing progress and errors to a human. Specify streams and failure behavior; no application is implemented.
2. A command currently prints a welcome banner before its structured output. A downstream parser fails. Prepare a contract correction that preserves useful human diagnostics.
3. A command has already produced part of its output when a later item fails. Specify an honest failure contract without pretending partial output is a complete success.

## CLI-002

1. A file-processing command receives two literal paths, '-draft.txt' and 'annual report.txt'. Design an operand contract that preserves their identity. No existing option grammar or shell environment is supplied.
2. A command's user asks whether '-' means standard input or a file literally named '-'. Its documented grammar does not say. Prepare a bounded specification without assuming an existing convention.
3. An application passes an untrusted filename containing spaces and shell metacharacters to a helper command. Specify a literal-argument handoff and tests without executing that filename as a command.
